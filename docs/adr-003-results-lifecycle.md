# ADR-003：结果与执行生命周期

状态：生效。日期：2026-09-17。

## 为什么改变旧策略

在 codex-mcp 的实际使用中，大结果自动落盘会增加重读和包装解析；
结构化结果与相同 JSON 的文本镜像也会重复占用宿主与模型的响应预算。
exec-mcp 把选择信息的责任交给能够执行 JavaScript 的 Agent，
不再维护一套“替模型管理上下文”的低阈值政策。
这是一项简化取舍，不是声称网络、宿主或内存从此没有限制。

## 结果只表达一次

不同时发送 `structuredContent` 和同一 JSON 的 TextContent 镜像。
接入下游结果时，优先保留结构化数据，仅移除可以无损证明等价的文本镜像；
独立说明、错误、图片、音频、资源及内容块的必要元数据不能顺手丢掉。
宿主专用的顶层私有 `_meta` 不进入模型，但不能因此递归删除内容块的公开元数据。
不能通过有损 parse/stringify 来判断含大整数、重复键或不同数字表示的文本是否相同。

本机结构化函数直接把对象交给 JavaScript；下游 MCP 保留明确的 CallToolResult 语义。
`text()` 的显式输出也不能在顶层回复里被再次复制成一份完整结构化镜像。
`structuredContent` 的存在不代表调用成功，必须保留 `isError` 和独立失败信息。
区分字段缺失与合法的 null、数组或标量，不把旧版的“只能是对象”规则扩散到所有下游。

[MCP 结构化结果规范](https://modelcontextprotocol.io/specification/2026-07-28/server/tools#structured-content)
为旧客户端兼容建议附带文本镜像，并非无条件强制。
本项目明确选择去重，并在目标 ChatGPT 路径验证可见性；
不能只为尚无实际消费者的兼容性恢复双份 JSON。

## Agent 管信息量，服务管真实资源

默认不施加 10,000 字符/码点或其他固定模型输出预算，也不自动落盘。
不创建通用 `outputFile` 引用与重读工作流。Agent 自己选择分页、过滤、摘要、增量读取，
或明确使用 Shell 重定向到文件；未请求限量时不能悄悄删掉信息。

支持 Agent 显式指定 `exec.max_output_tokens`（也可放在首行 pragma）和 `wait.max_tokens`；
同名顶层参数优先，省略不限量，wait 不继承 exec 的预算。这样保留 Agent 的控制权，
而不是重新引入旧服务的强制截断政策。预算仅作用于本次返回的显式文本，不限制嵌套结果或 store。
沿用 Codex 约四个 UTF-8 字节/token 的轻量估算，保留首尾并提示截断；不宣称精确模型 token 数。
host 返回的媒体原样保留，状态、cell_id 和截断提示不计入预算；本服务不因文本预算额外估算或丢弃音频。
媒体 helper 自身遵循固定 host 的原生规则，包括将无法可靠处理的过短 WAV 改为说明文本；
不在外层绕过这些行为，也不另写一套音频检测或过滤逻辑。
零预算仍返回必要状态和媒体。截断后的文本未必是有效 JSON，被省略的内容不会在下一次 wait 补发，
需要后续处理的数据应先 store；这不是结果分页服务。
显式导出的原生文件链接同样不受文本预算影响；这不是自动落盘，见 [ADR-005](adr-005-file-transfer.md)。

仍然保护请求、目录、嵌套结果和总响应的真实传输大小，以及 V8 与并发执行的资源消耗。
**48 MiB 是单次已编码载荷的宽松保护参考，不是进程总内存上限，也不是模型上下文预算。**
参考 host 的 [64 MiB IPC frame 上限](https://github.com/openai/codex/blob/8b78600dc85cc265d7e7e827f6aa903875405287/codex-rs/code-mode-protocol/src/host/codec.rs)，
实际保护值必须按固定版本、所选 transport、编码开销和宿主限制验证，最终以代码为准。
SDK 可能先缓冲完整响应，多个调用也会并发占用内存；不能把单载荷限制宣传成严格 RSS 保证。

超过真实边界时返回明确错误，不静默截断、不自动溢写文件：
输入过大应在操作前拒绝；结果过大可能发生在副作用之后，必须说明结果不可交付、不要自动重试。
超限的嵌套结果可能尚未进入 JavaScript，因此不能承诺 Agent 总能事后缩减它；
需要在下一步检查实际状态，并选择更小的查询或明确的输出目的地。
终端增量读取和必要的背压属于进程管理，不因此引入持久结果存储产品。

## cell 与进程是两个生命周期

每次 exec 仍使用新的 V8 isolate，不共享普通 JS 变量、函数或隐式当前目录；显式数据共享见下节。
只有仍运行的脚本返回 `cell_id`；`wait` 仅续取该脚本的新增输出或终止它。
句柄是不透明的临时标识，不是任务 token、身份或授权证明，也不承诺服务重启后恢复。

命令返回 `session_id` 后由终端管理器持有，不依附于外层 cell。
后续输入、轮询和终止通过新的 exec 内的 `tools.write_stdin` 完成；
不要拿 `cell_id` 当进程句柄，或把完成 cell 理解成结束进程。
正常服务关闭负责清理自有进程；异常退出后不能冒称原命令已经撤回或从未执行。

取消是尽力请求，不是事务回滚。仅取消一次等待不等于终止整个执行；
明确终止 cell 时取消仍在等待的嵌套调用，不顺便杀掉已经交回 session_id 的独立进程。
超时、断连、host 崩溃和输出失败均可能留下已发生的副作用。
可恢复服务连接，不自动重放脚本、补丁或下游调用；先观察效果再决定下一步。

不提供 Codex 的 `notify()` 注入语义，不以静默丢弃或普通 MCP 通知冒充支持。
保留显式 `text`、媒体输出、`yield_control` 和 `wait`；未 await 的 Promise 不属于可靠后台任务。
为这些临时执行维护必要内存状态，但不增加持久任务数据库、自动续跑或跨重启执行保证。

## 对话内的 store/load，以原生 host 为准

直接使用固定版本 Code Mode host 的同步 store/load。同一 ChatGPT 对话复用原生 session，
每次 exec 仍创建独立 V8 isolate；跨 exec 保存的是 host 进程内的 JSON 数据，不写磁盘。
不修改 host 源码或二进制，也不再在外部实现第二套缓存、写入记录桥接或存储提交协议。

撤销曾增加的单对话/全局存储字节配额、键数/对话数配额、16-cell 准入上限和容量压力回收。
删除自定义 store.delete/clear/stats，回到原生 store/load；不要把“减少内存增长风险”自动升级成
一套与 Codex 不同的缓存产品。48 MiB 编码边界和每个 isolate 的堆设置是已有的不同边界，
不是这次撤销的 store 配额，不声称它们约束原生 session 的共享存储总量。

关联采用宿主 `_meta["openai/session"]` 的对话标识，仅保存摘要，不以 HTTP 连接、单轮消息或工作目录区分。
不同对话的存储隔离；缺失标识时普通 exec 可用，store/load 明确报错，不退回全局共享。
标识只用于当前可信单操作者入口的关联，不代替认证。

遵循原生语义：新 cell 读启动快照，load 返回副本，修改后需再次 store。
写入在 host 完成 cell 时合并，不再等外层 exec/wait 收取结果；脚本报错前的写入也可能提交，
终止尚未提交的 cell 不发布这些写入。并发同键不是事务，store/load 不是运行中 cell 的实时通信机制。
单个 cell 完成或终止不得关闭同一对话的其他 cell；完成结果仍可通过原 cell_id 后续取回。

保留最小生命周期清理：所有 cell 已收尾后，连续空闲 72 小时才关闭原生 session 并释放数据，
使用会刷新空闲时间；活动或结果待取的 cell 不因这条时间规则被清理。不按容量压力提前淘汰缓存。
服务或 host 重启会丢失原生存储，不提供持久化或自动恢复承诺。

接受的代价是：持续活跃的对话若不断增加新 key 或放入更大的值，内存仍可能增长；
覆写相同 key 不保留历史版本，但原生 host 没有我们曾加上的存储总配额。
不再承诺长期运行的内存一定有界。需要长期保留或体量很大的数据应显式写文件，
操作者可以观察内存并自行决定何时重启，不默认新增自动重启、自动落盘或复杂淘汰策略。

## generatedImage 是输出，不是生成服务

保留原生 `generatedImage({image_url, output_hint?})`：输出已存在的 base64 data URL 图片，
并把可选字符串说明作为独立文本输出。不调用生成 API、不下载 HTTP URL、不自动保存或发布文件。
图片走 MCP 原生媒体内容，不附加 JSON 文本镜像；output_hint 按显式文本预算处理。

## 在 Connector 超时前返回进度

为减少 [ADR-001](adr-001-exec-runtime.md) 中的外层调用开销，`exec.yield_time_ms` 保持 0–30 秒；
`wait.yield_time_ms` 范围改为 0–110 秒，默认值、推荐值和上限均为 110 秒（`110000` ms）。

以目标 Connector 调用超时不少于 120 秒作为设计假设，而非上游保证；预留 10 秒传输与调度余量，
让 wait 在该超时窗口内正常返回执行状态和脚本显式输出的新增进度，避免长等待只换来超时报错。
110 秒是单次最长等待，不是固定休眠或 cell 执行期限；完成、主动 yield 或终止时提前返回。
