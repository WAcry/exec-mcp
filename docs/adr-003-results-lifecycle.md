# ADR-003：结果与执行生命周期

状态：生效。日期：2026-09-17。

## 为什么改变旧策略

在 codex-mcp 的实际使用中，大结果自动落盘会增加重读和包装解析；
结构化结果与相同 JSON 的文本镜像也会重复占用宿主与模型的响应预算。
exec-mcp 把选择信息的责任交给能够执行 JavaScript 的 Agent，
不再维护一套“替模型管理上下文”的低阈值政策。
这是一项简化取舍，不是声称网络、宿主或内存从此没有限制。

## 结果只表达一次

不同时发送 `structuredContent` 和同一 JSON 的 TextContent 镜像。
接入下游结果时，优先保留结构化数据，仅移除可以无损证明等价的文本镜像；
独立说明、错误、图片、音频、资源及内容块的必要元数据不能顺手丢掉。
宿主专用的顶层私有 `_meta` 不进入模型，但不能因此递归删除内容块的公开元数据。
不能通过有损 parse/stringify 来判断含大整数、重复键或不同数字表示的文本是否相同。

本机结构化函数直接把对象交给 JavaScript；下游 MCP 保留明确的 CallToolResult 语义。
`text()` 的显式输出也不能在顶层回复里被再次复制成一份完整结构化镜像。
`structuredContent` 的存在不代表调用成功，必须保留 `isError` 和独立失败信息。
区分字段缺失与合法的 null、数组或标量，不把旧版的“只能是对象”规则扩散到所有下游。

[MCP 结构化结果规范](https://modelcontextprotocol.io/specification/2026-07-28/server/tools#structured-content)
为旧客户端兼容建议附带文本镜像，并非无条件强制。
本项目明确选择去重，并在目标 ChatGPT 路径验证可见性；
不能只为尚无实际消费者的兼容性恢复双份 JSON。

## Agent 管信息量，服务管真实资源

对顶层工具最终模型可见文本采用 36,000 UTF-8 字节的保守总边界，包含状态和提示，
超量保留首尾并明确标注；依据是目标 ChatGPT 链路的实测，不将其宣传成永久统一的 10,000-token 定律。
不创建通用 outputFile 引用或自动落盘工作流。主要路径仍是 Agent 在 Code Mode 中筛选完整嵌套结果，
或在本次执行结束前用原生 store 保存供后续 load；也可显式使用 Shell 写文件。

支持 exec.max_output_tokens（及首行 pragma）和 wait.max_tokens 缩小本次文本预算；
同名顶层参数优先，wait 不继承 exec 的显式预算。省略参数仍经过最终出口保护，
而不是把同一个小限额传给所有嵌套工具。输入、嵌套结果和 store 保持独立的真实资源边界。
沿用 Codex 约四个 UTF-8 字节/token 的轻量估算，保留首尾并提示截断；不宣称精确模型 token 数。
host 返回的媒体原样保留，状态、cell_id 和截断提示不计入显式 token 预算，但计入最终文本总边界；本服务不因文本预算额外估算或丢弃音频。
媒体 helper 自身遵循固定 host 的原生规则，包括将无法可靠处理的过短 WAV 改为说明文本；
不在外层绕过这些行为，也不另写一套音频检测或过滤逻辑。
零预算仍返回必要状态和媒体。截断后的文本未必是有效 JSON，被省略的内容不会在下一次 wait 补发，
需要后续处理的数据应先 store；这不是结果分页服务。
直接工具的小对象只返回 structuredContent，不附相同 JSON 文本；字符串和图片使用原生 content。
超大直接结果退化为有标记的首尾文本，单独保留命令/补丁状态与终端句柄，不创建 cell、落盘或重放操作。
因此直接 MCP 边界不声明强制 outputSchema；exec 内完整原始值仍遵循其目录契约。
显式导出的原生文件链接同样不受文本预算影响；这不是自动落盘，见 [ADR-005](adr-005-file-transfer.md)。

Web 用户补充随正常结果同通道附带：结构化结果包装为 result/user_notes，文本结果追加简短标题与正文，
媒体和资源保留原生块。总文本可至 37,000 UTF-8 字节；只利用剩余额度，不缩小普通结果、不截断补充。
该队列与 store/审计独立，见 [ADR-010](adr-010-session-notes.md)。

仍然保护请求、目录、嵌套结果和总响应的真实传输大小，以及 V8 与并发执行的资源消耗。
**48 MiB 是单次已编码载荷的宽松保护参考，不是进程总内存上限，也不是模型上下文预算。**
参考 host 的 [64 MiB IPC frame 上限](https://github.com/openai/codex/blob/8b78600dc85cc265d7e7e827f6aa903875405287/codex-rs/code-mode-protocol/src/host/codec.rs)，
实际保护值必须按固定版本、所选 transport、编码开销和宿主限制验证，最终以代码为准。
SDK 可能先缓冲完整响应，多个调用也会并发占用内存；不能把单载荷限制宣传成严格 RSS 保证。

超过真实边界时返回明确错误，不静默截断、不自动溢写文件：
输入过大应在操作前拒绝；结果过大可能发生在副作用之后，必须说明结果不可交付、不要自动重试。
超限的嵌套结果可能尚未进入 JavaScript，因此不能承诺 Agent 总能事后缩减它；
需要在下一步检查实际状态，并选择更小的查询或明确的输出目的地。
终端增量读取和有界日志缓冲属于进程管理，不因此引入持久结果存储产品。

终端日志按进程会话独立保留未读头部与滚动尾部，超出缓冲容量丢弃中间内容。
默认缓冲放宽到 16 MiB、单次读取 4 MiB，使 Code Mode 能在正常大结果中搜索中间信息；
这与最终模型文本预算不同。容量可配置，比例由代码维护：计量用 UTF-8 字节而不是行数，避免巨大单行绕过上限；
前缀属于当前尚未交付的批次，已读的启动信息不在每次调用中重复。
返回 truncated/omitted_bytes 及间隙处的说明，不假装截断后的 JSON 或日志仍完整；
丢弃的字节不会在后续读取恢复。需要完整输出时由调用方显式写文件。

缓冲在接收时即限量，不先无限保留再在返回时缩短；复制有限片段、合并小写入，
不能用小 subarray 留住原本的大块，也不能为每个单字符写入保留一个对象。
不同终端独立收取输出，不暂停其他会话；不自动落盘，不限制用户生成文件的大小或剩余磁盘空间。
缓冲容量不包含底层管道/PTY、当前在途块与结果编码的短期副本，不宣传成整个 Node 进程的 RSS 上限。
进程已退出且长时间没有读取的剩余记录可以过期释放；运行中进程不因这条空闲记录策略被杀掉。

## cell 与进程是两个生命周期

每次 exec 仍使用新的 V8 isolate，不共享普通 JS 变量、函数或隐式当前目录；显式数据共享见下节。
只有仍运行的脚本返回 `cell_id`；`wait` 仅续取该脚本的新增输出或终止它。
句柄是不透明的临时标识，不是任务 token、身份或授权证明，也不承诺服务重启后恢复。

命令返回 `session_id` 后由终端管理器持有，不依附于外层 cell。
后续输入、轮询和终止通过直接 write_stdin 或 exec 内同名工具完成；两者共享同一进程句柄和增量读取状态。
不要拿 `cell_id` 当进程句柄，或把完成 cell 理解成结束进程。
正常服务关闭负责清理自有进程；异常退出后不能冒称原命令已经撤回或从未执行。

write_stdin 统一等待进程结束或 yield_time_ms 到期；写入和仅读取默认及最长均为 110 秒，两种入口共用同一契约。
移除 wait_for，不保留按日志提前返回的模式；已有和新增日志只进入原有有界缓冲，不唤醒等待、不重置截止时间。
默认长等待减少模型的轮询往返，进程提前结束就返回；及时交互由较短窗口控制，零等待立即读取。
这是有意的行为变更：过去省略参数的交互式读取或写入会及时返回，现在需要显式缩短窗口。
不新增 sleep 工具、后台轮询任务或日志落盘：sleep 无法在进程结束时提前返回，也不会自行收取结果。
取消等待只移除本次观察，不消费输出、不终止已交回句柄的进程；显式 terminate 保持原有语义。
等待观察者在返回或取消时解除，不能为长期运行的进程不断累积不可移除的结束回调。
等待更久不扩大终端缓冲、单次读取或最终模型输出预算；已退出但输出未读完时继续返回相同 session_id。

取消是尽力请求，不是事务回滚。仅取消一次等待不等于终止整个执行；
明确终止 cell 时取消仍在等待的嵌套调用，不顺便杀掉已经交回 session_id 的独立进程。
超时、断连、host 崩溃和输出失败均可能留下已发生的副作用。
可恢复服务连接，不自动重放脚本、补丁或下游调用；先观察效果再决定下一步。

不提供 Codex 的 `notify()` 注入语义，不以静默丢弃或普通 MCP 通知冒充支持。
保留显式 `text`、媒体输出、`yield_control` 和 `wait`；未 await 的 Promise 不属于可靠后台任务。
为这些临时执行维护必要内存状态，但不增加持久任务数据库、自动续跑或跨重启执行保证。

## 对话内的 store/load，以原生 host 为准

直接使用固定版本 Code Mode host 的同步 store/load。同一 ChatGPT 对话复用原生 session，
每次 exec 仍创建独立 V8 isolate；跨 exec 保存的是 host 进程内的 JSON 数据，不写磁盘。
不修改 host 源码或二进制，也不再在外部实现第二套缓存、写入记录桥接或存储提交协议。

不恢复单对话存储配额、键数/对话数限制或 16-cell 准入上限；压力策略采用下文的整 session 回收。
删除自定义 store.delete/clear/stats，回到原生 store/load；不要把“减少内存增长风险”自动升级成
一套与 Codex 不同的缓存产品。48 MiB 编码边界不是原生 session 的存储总量上限；
固定 host 0.155.1 忽略 max_heap_size_bytes，不能把该字段或旧的 256 MiB 常量宣传成单 cell 的有效保护。

关联采用宿主 `_meta["openai/session"]` 的对话标识，仅保存摘要，不以 HTTP 连接、单轮消息或工作目录区分。
不同对话的存储隔离；缺失标识时普通 exec 可用，store/load 明确报错，不退回全局共享。
标识只用于当前可信单操作者入口的关联，不代替认证。

遵循原生语义：新 cell 读启动快照，load 返回副本，修改后需再次 store。
写入在 host 完成 cell 时合并，不再等外层 exec/wait 收取结果；脚本报错前的写入也可能提交，
终止尚未提交的 cell 不发布这些写入。并发同键不是事务，store/load 不是运行中 cell 的实时通信机制。
单个 cell 完成或终止不得关闭同一对话的其他 cell；完成结果仍可通过原 cell_id 后续取回。

### 对话标识与原生执行身份分开

_meta["openai/session"] 是宿主提供的对话关联键；本服务只保留其摘要，不修改该元数据，也不要求用户换聊天。
它不是 MCP HTTP transport 的 session ID，不是 Code Mode host 的 session ID，更不是 exec 的 cell_id 或终端 session_id。
同一对话在不同时刻可绑定不同的原生 session。首次打开和回收后第一次重新打开都会获得全新原生 session，
新 exec 从空 store 开始并在状态中提示；无元数据时仍不发明一个全局共享对话。

回收先同步解除“对话摘要 → 旧实例”绑定，再异步关闭旧实例。关闭尚未完成时，同一对话的新 exec
即可创建下一代 session；同一新一代的并发打开继续合并成一次 OpenSession。
旧关闭回调、失败回调、晚到结果和租约释放只关联它持有的旧实例，不能按对话名称删除新实例。
原生 ID 即使在 host 重启后重用，也不是唯一身份；隔离以实例对象和 host 代次为准。
旧 cell_id 不路由到新 session，后续 wait 明确说明回收及副作用不确定，不能自动重播脚本。

### 宽松的原生 host 压力保护

[memory] 配置提供 host 高水位、空闲保留期和每终端缓冲容量，具体默认值由代码/用户配置说明维护。
只采样自有 Code Mode host 的近似 RSS/working set，不采样 Node heapUsed 代替它，也不统计或限制用户的浏览器、编译器等子进程树。
Linux 读取 /proc，macOS 用系统 ps，Windows 用系统 Get-Process；不引入常驻监控进程或修改固定 host。
测量失败只报告诊断，不当作内存超限。按进程实例校验采样，过期样本不能用于新 host。

正常情况下，所有 cell 收尾后连续空闲 72 小时才释放 session（可配置）；
压力下先按进入空闲的时间 FIFO 关闭空闲 session，清理目标约为高水位的 75%。
已经低于高水位时不为凑到 75% 而牺牲活动会话；没有空闲候选且仍超高水位时，
按最近一次 exec/wait 的使用时间回收最旧的未收尾 session，接受该 session 的多个 cell/store 一起丢失。
一次只关闭一个再重新测量，不凭猜测做单 cell 评分或逐 key 清理。
一轮只处理开始时已存在的代次，关闭过程中创建的新 session 留给下一轮检查，避免刚恢复就被旧清理追杀。

关闭超时后只有内存仍超高水位才重启共享 host；所有 session 已释放但内存仍高时也可回收 host。
共享 host 重启是故障兜底，会影响其中的其他执行，必须明确报告而非声称完全隔离。
重启时短暂拦住新的打开，完成后延迟启动新 host；已发往旧实例的命令可失败或丢结果，但不自动重放。
即使一次打开/关闭失败，对话关联键也不能永久失效；后续 exec 仍可新建干净实例。
强制终止也使用有限确认时间；无法确认时返回错误并允许以后再次尝试恢复，不永久挂住打开屏障，也不并行启动第二份未确认的 host。
失效句柄说明是有时效、有数量上限的诊断记录，不是被禁用的对话名单。

这是压力回收而非操作系统硬限额；采样间隔、瞬时分配和原生分配器会造成越线，
不能承诺恶意脚本或任意外部程序永不耗尽内存。重要持久状态仍由调用方明确写文件。
不增加存储复制、持久任务、自动重试或日志溢写；不因回收 cell 而终止已经交回终端 session_id 的独立进程。

## generatedImage 是输出，不是生成服务

保留原生 `generatedImage({image_url, output_hint?})`：输出已存在的 base64 data URL 图片，
并把可选字符串说明作为独立文本输出。不调用生成 API、不下载 HTTP URL、不自动保存或发布文件。
图片走 MCP 原生媒体内容，不附加 JSON 文本镜像；output_hint 按显式文本预算处理。

## 在 Connector 超时前返回进度

为减少 [ADR-001](adr-001-exec-runtime.md) 中的外层调用开销，`exec.yield_time_ms` 保持 0–30 秒；
`wait.yield_time_ms` 范围改为 0–110 秒，默认值、推荐值和上限均为 110 秒（`110000` ms）。

以目标 Connector 调用超时不少于 120 秒作为设计假设，而非上游保证；预留 10 秒传输与调度余量，
让 wait 在该超时窗口内正常返回执行状态和脚本显式输出的新增进度，避免长等待只换来超时报错。
110 秒是单次最长等待，不是固定休眠或 cell 执行期限；完成、主动 yield 或终止时提前返回。

## 执行状态与辅助诊断

Script completed 表示 JavaScript 编排完成，不表示嵌套命令都成功；命令退出码沿用 Shell 原生语义。
管道累计 stderr_bytes 辅助识别错误流，不据此强判失败；PTY 不虚构分流。原生工具和下游 MCP 的
非零退出/明确错误分别记为子调用异常，不污染对话组永久健康状态。
原生 SyntaxError 后才辅助解析实际 source，提供指纹、请求 ID 及可定位的行列片段；
不预执行另一份脚本，也不让辅助解析器成为原生 V8 的语法门槛。
