# ADR-010：Web 会话补充消息

状态：生效。日期：2026-09-20。

## 用户主动补充，不恢复异步问答

操作者在 Web 的现有会话组中发送补充，由同一对话下一次工具自然返回时附带。
不增加 MCP 工具、查询收件箱、确认参数、浏览器通知或 Agent 提问流程；不恢复已删除的问答数据库。
默认按会话哈希展示，只允许操作者手动设置备注名，不让 ChatGPT 生成名字。备注仅用于 Web 辨认，不参与路由或进入模型消息。

归属沿用 `_meta["openai/session"]` 的 SHA-256 摘要，而非连接、原生 session、cell、终端或目录。
仅从带有此标识的实际工具调用发现收件人；缺失标识的组不能发送。所有顶层工具共用附带逻辑，
成功、运行中及普通执行错误均可携带，嵌套工具原值、tools/list、资源读取与 Web 查询不消费消息。
在返回时选取，因此等待期间提交也有机会搭上当前响应；消息不唤醒长等待、不改写已运行脚本，也不是紧急停止或审批机制。

## 只使用剩余额度

普通工具结果保持原有 36,000 UTF-8 字节保护；有补充时合计最多 37,000 字节。
按正常结果的文本及 structuredContent 的 JSON 表示计费，再按 FIFO 加入完整消息，包含消息编号、时间和封装。
不为消息重新裁剪正常结果，不拆分或截断消息，不跳过放不下的队首。队首一直放不下就继续排队，这是有意接受的简单取舍。
不宣称这些字节值等于 ChatGPT 永久固定的 token 上限。媒体与原生文件保留，真实编码载荷上限仍需独立检查。

选取、检查与标记附带在同步步骤中完成，避免并发响应重复消费；同一批按序排列，跨响应抵达顺序不作网络保证。
附带前已取消或编码失败则保持待发。附带后不重发，也不要求模型确认；UI 写“已附入工具响应”，不能称已读或已执行。
连接器途中丢失响应可能丢失本次投递，用户保留复制入口；不为这项低频补充引入确认协议。

## 生命周期与 Web 边界

消息及备注保存在独立的有界实例内存中，不随审计滚动、清空历史或原生 host 回收删除。
执行服务重启复用它；整个程序退出后不恢复。按需清理 72 小时旧记录，计费容量约 16 MiB，满时拒绝新提交而不覆盖待发消息。
正文按 30,000 UTF-8 字节校验，保留原文；浏览器用提交 ID 去重，内容变化作为新消息。仅待发消息可撤回。
实际 Web 监听期间发现新的可用收件人；关闭 Web 不删除既有消息，原对话后续调用仍可携带。

沿用 Web 同源、鉴权和写请求标记；SSE 只发变化通知与会话摘要，不广播消息正文。
草稿按收件人隔离，提交成功后才清空对应草稿；备注和正文按纯文本渲染。
这是可信单操作者的沟通通道，不以同账户进程可访问的 Web API 冒充只有真人能授权的安全边界。
