# ADR-003 结果与执行生命周期

[English](003-results-lifecycle.md) | 简体中文

当前生效，2026-11-08 更新。

## 结果去重与展示

structuredContent 与等价 JSON 文本只保留一份。处理下游结果时，仅删除可以无损证明重复的文本，
保留独立说明、isError、媒体、资源及内容块元数据；宿主私有的顶层 _meta 不进入模型。
比较时保留大整数、重复键与数字表示的差异，避免有损 parse/stringify 误删内容。
结构化数据仍需结合 isError 判断，字段缺失也须与合法 null、数组或标量分别处理。

本机函数将原值交给 JS，下游保留 CallToolResult。脚本通过 text/image/audio/generatedImage 显式输出，
导出链接独立附带，见 [ADR-005](005-file-transfer.zh.md)。显式输出只发送一次，省去无实际消费者的兼容镜像。

as_settled 与 stream_settled 复用原生 host 的实现，逐项处理已完成的 Promise。
脚本选择输出内容，text 记录结果，yield_control 或观察期限通过 exec/wait 返回结果。
这沿用普通 MCP 响应，无需异步注入模型消息，也不改变结果预算。

大结果由 Agent 在 Code Mode 中筛选，或用 store 保存后分段 load；需要持久内容时可显式写文件。
服务不自动把通用结果写盘，以免增加重读、路径解析和结果清理步骤。
最终响应采用目标链路实测得出的保守 UTF-8 字节上限，超限保留首尾并提示。
包括最终限额处理在内，保留的文本、媒体和资源维持相对顺序；只允许合并相邻的纯文本块。
被省略的内容不会由后续 wait 补发，截断文本也可能失去 JSON 语法完整性。宿主的实际 token 限制仍可能变化。

exec.max_output_tokens 与 wait.max_tokens 分别缩小本次文本预算，外层参数优先于首行 pragma；
wait 不继承 exec 的显式值。token 数量使用轻量估算，状态、句柄及已保留的媒体继续保留，并计入相应最终载荷限制。
外层响应预算保留交给 JS 的嵌套原值；各工具仍执行自身的输出与传输限制，过大的原值可能在到达 JS 前就被拒绝。
输入过大在操作前拒绝，结果过大则可能发生在操作之后，此时不能自动重试。

原生会话在未修改的官方 host 上选择 [SERVER 输出截断](https://github.com/openai/codex/blob/rust-v0.167.0/codex-rs/code-mode-protocol/src/session.rs)，
运行 cell 前必须收到明确的 SERVER 确认；确认缺失或不兼容时取消会话。
这用原生[有界收集器](https://github.com/openai/codex/blob/rust-v0.167.0/codex-rs/code-mode-runtime/src/output/output_collection.rs)替代此前的 CLIENT 选择。
每次观察的文本、编码图片/音频 URL 及条目上限见[配置指南](../guides/configuration.zh.md#容量与临时状态)。
文本保留头部与滚动尾部；媒体按源顺序整项接纳，分别消耗对应额度；条目数量压力也可能驱逐媒体。

传给原生 host 的 Execute、Wait 和 Terminate 都使用 Number.MAX_SAFE_INTEGER 作为内部 maxOutputTokens。
这让原生展示预算不再限制通常已保留的输出，既不扩大收集器容量，也不按该数值分配内存。
Node 继续负责调用者的纯文本预算与最终 MCP 文本上限，因此调用者的零文本预算本身不会丢弃已保留的音频。
原生音频校验仍然生效，包括 PCM WAV 至少 25 毫秒的要求；极端时长元数据仍可能耗尽原生格式化器的有限音频预算。
适配层把原生输出丢失计数和音频省略诊断放入状态区，避开调用者的文本预算，并在最终文本上限内保留；正文的缺口标记保持原有顺序。
识别采用固定 host 的精确文本格式；协议没有结构化的来源标识，脚本可以仿写这些提示。解释只影响展示，不影响执行或重放决策。
后续 wait 不能补回省略内容。脚本错误由原生格式化器给出，适配层仅用错误元数据判断状态，不再追加一份错误文本。

接受原生媒体省略的代价，以获得有界的显式输出保留量，并继续使用官方 host。
CLIENT 能在传输限制内交付更大媒体，但没有限制这部分保留量；本地修改 host 可以改变这些策略，代价是维护另一份运行时实现。
只保留一种协商模式，不提供 CLIENT 开关或运行时 fork。调用者按[媒体示例](../guides/code-mode-examples.zh.md#转发音频与交付较大媒体)选择小批次、图片变换或源文件导出。
原生事件通道按事件数量设限并施加背压，但不限制单次分配、JS 堆、store 或全部并发 cell 的内存总量。
收集额度与传输上限独立：组合媒体或序列化开销仍可能让结果无法交付，而操作已经生效。
传输限制和采样式进程内存回收继续生效，突发分配仍可能在采样前耗尽内存。交付失败从不自动重放工作。

用户补充与普通结果使用同一文本通道，只占剩余额度。完整消息放不下就继续排队，
不压缩普通结果，见 [ADR-010](010-session-notes.zh.md)。
默认值和可调项见[配置指南](../guides/configuration.zh.md#容量与临时状态)，精确限制以 schema 和实现为准。
编码载荷大小与进程内存分别检查，SDK 缓冲、并发请求和短期副本都会增加内存占用。

## 终端日志

每个终端独立保留未读头部和滚动尾部，溢出时丢弃中间内容，并报告省略位置与字节数。
按字节计量可限制巨大单行；已读头部不重复返回。接收阶段就限制缓冲大小，
各会话独立处理，一个终端刷屏不会暂停其他终端。
exec_command 与 write_stdin 对每批收取的输出应用 max_output_tokens，默认 10,000，按每 token 四个 UTF-8 字节估算。
每次最多读取 4 MiB，预算保留该批首尾，省略的中间文本已消费，后续读取不会补回；批次之外的未读字节仍可通过 session_id 续取。
这样调用者选择的输出大小与缓冲内存上限分别管理。需要完整日志或数据时显式重定向到文件，文件大小与磁盘配额由用户管理。

已退出且久未读取的终端记录可过期，运行中的进程继续保留。
全部终端还共享两项上限：会话数量和未读输出总预算。达到任一上限时，先释放无人读取的已结束会话，最早的优先；
未读输出仍超出预算时，从产生新输出的会话开始丢弃运行中会话最早的未读尾部，并像其他省略一样标注。
上限从不停止运行中的进程：Codex 也把进程数限制在 64 个，但停止用户进程可能中断有副作用的工作。
只剩运行中的会话占满上限时，exec_command 返回错误，指明对应配置项，并提示调用者读取或终止会话。
系统管道、PTY 和在途副本会占用额外内存，因此终端缓冲容量只约束本服务保留的日志。

## cell、终端与等待

每次 exec 创建独立 V8 isolate，运行中的脚本通过 cell_id 续等或终止。
命令返回 session_id 后由终端管理器持有，可跨 exec 使用，外层 cell 结束后仍能继续操作。
这些句柄只在当前运行期间有效，调用权限由入口认证决定。
正常关闭会清理自有进程；异常退出后，已写入的文件和外部操作仍可能保留。
Windows 通过 taskkill 终止进程树，可能与 Shell 启动期创建子进程发生竞争；前台退出不证明所有后代均已停止。
运行中进程的终止测试先获得子进程 READY/PID，再验证该子进程退出。本次 Codex 升级没有改变这一已有的平台限制。

write_stdin 沿用固定 Codex 的收集窗口。非空写入默认等待较短时间，空输入可收集较长时间。
[上游收集器](https://github.com/openai/codex/blob/rust-v0.167.0/codex-rs/core/src/unified_exec/process_manager.rs)
持续收集日志，到截止时间或进程结束时返回。窗口在取得终端并完成写入或调整后开始，
排队及 stdin 背压不占用该窗口，新日志也不重置截止时间。显式 0 保留立即读取的能力。
延长等待不会扩大缓冲或输出容量。
主 Shell 退出后短暂、有界地收取剩余输出，保留输出消费完才交回退出码。
后代进程可能继续持有继承的管道，但不会因此让终端观察一直等待；这段收尾不会向它们发送终止信号。

内层工具可以运行超过一次外层等待窗口。exec 默认使用最长 30 秒的观察窗口，与固定 Codex Core 一致，并减少 ChatGPT 首次调用的往返；
脚本仍在运行时先交回 cell_id，再由 wait 续取结果。
外层 wait 特意保留默认及最大 110 秒：较长观察减少 ChatGPT 重复往返和 token 消耗，
同时依据目标 connector 超时不少于 120 秒的工程假设，为传输留出余量。完成、主动 yield 或终止可以提前返回；新的用户补充也可提前结束观察，见 [ADR-010](010-session-notes.zh.md)。
当前没有独立 sleep 工具、后台模型轮询或持久任务调度。

取消一次 wait 只停止观察；终止 cell 会请求取消尚未完成的嵌套调用。
取消 exec 请求会终止其 cell。host 尚未报告 cell 时，取消立即返回，
服务在收到 cell ID 后再终止该 cell；已取消 exec 的工具调用不再执行。
工具结果交付与取消发生竞态时按取消处理，不会使原生 session 失效。
已交回 session_id 的终端仍需显式终止。观察者退出后解除监听，尚未交付的输出留待后续收取。
取消、断连、host 故障或结果交付失败都可能留下已生效的操作，恢复连接后不自动重放脚本或下游调用。
脚本须等待需要完成的 Promise；未 await 的操作可能被丢弃。notify 的宿主消息注入尚未接入。

yield 后的 cell 在 wait 取回最终结果前一直占用原生 session，其 store 和内存也随之保留。
在空闲保留期内没有任何 wait 观察的 cell 会被终止并释放 session，此后该 session 按常规空闲保留处理。
进行中的 wait 算作观察，包括排在其他 wait 之后的调用。
之后对该 cell_id 的 wait 会返回原因；未读输出丢失，副作用保留，它启动的终端继续独立存在。
另一种做法是保留无人观察的 cell 直到内存压力出现，这会让无人读取的对话超出空闲保留期仍占用资源。

## 原生 store/load

同一 ChatGPT 对话复用原生 session，在 host 内保存可序列化数据。普通 JS 变量随 isolate 结束，
store 数据也不会自动写盘。使用固定 host 的同步 store/load，保持二进制不变，
不另设逐 key 协议、对话小配额或自定义 delete/clear/stats。传输限制单独生效；
固定版本会忽略部分 heap 配置，不能将这些字段计作有效内存保护。

每个 cell 读取启动快照，load 返回副本。写入在 cell 完成时合并，脚本错误前的写入也可能提交；
终止尚未提交的 cell 会丢弃这些写入。并发同键写入没有事务保证，运行中的 cell 也不能通过 store/load 实时通信。
单个 cell 收尾后，同一对话的其他 cell 继续存在；空闲保留期内，完成结果仍可通过原 cell_id 收取。

对话使用宿主 openai/session 的摘要分组，同一对话跨连接、跨轮次或换目录时继续关联。
缺少标识时普通执行仍可用，store/load 报错，不创建全局共享存储。身份认证由接入层负责。

## 内存回收与对话恢复

宿主对话标识和原生 session 代次分别管理。运行时故障或内存回收后，恢复流程准备新 session，
在执行更多源码前先告知原状态丢失。触发恢复的 exec 及已经排在旧代次中的调用都不执行其脚本，
下一次新 exec 才可使用新 session。既有副作用可能保留，因此先让 Agent 检查实际状态再决定如何继续。
旧关闭回调、晚到结果及租约只影响旧代次，旧 cell 不转入新 session，也不自动重播。
正常空闲过期后，下一次 exec 照常建立新 session，并附已有的新 session/store 为空提示；故障标记沿用同一空闲保留期。

只采样自有 Code Mode host 的近似 RSS/working set，用户启动的浏览器、编译器等进程树由用户管理。
0.167.0 协议中的可选 metrics RPC 未启用：发布包的独立 host 未配置 collector，会返回 UNIMPLEMENTED，因此仍需平台采样。
测量失败时报告诊断，过期样本不用于判断新 host。正常情况下，所有 cell 收尾后保留空闲会话；
内存超过高水位时，按进入空闲的时间 FIFO 回收，再测量。
没有空闲候选且仍超高水位时，回收最久未使用的活动 session，其多个 cell 和 store 可能一起丢失。
低于高水位就停止回收活动会话，一轮只处理开始时已存在的代次，新实例留给下一轮检查。

关闭失败且内存仍高，或释放全部状态后内存仍高时，可以重启共享 host。
重启会影响其中其他原生会话。服务把重启及原因写入 stderr，之后对丢失 cell 的 wait 返回回收说明。
host 意外退出也会连同 host 最近的 stderr 输出一起写入 stderr。
无法确认旧 host 已终止时，拒绝并开新 host，后续可重试恢复。
采样和回收存在延迟，瞬时分配仍可能耗尽内存。独立终端继续保留，持久数据由调用方显式写文件。

## 执行状态与诊断

Script completed 记录 JS 已完成，嵌套命令的成败仍按各自结果判断。Shell 退出码保持原生语义，
stderr 字节数只供辅助判断，PTY 的合并输出不另设错误流计数。会话组按当前状态展示，
历史子调用失败不使它永久告警。

原生 host 报 SyntaxError 后，服务才辅助解析实际收到的源码，提供指纹和可定位的片段。
辅助解析用于诊断，不拦截 V8 语法，也不执行修改后的源码。
view_image 读取本地图片并返回 {image_url, detail}；image_url 是 data URL，detail 是宿主提示。脚本通过 image(await tools.view_image(...)) 展示。
generatedImage 输出已有 data URL 和说明，图片生成、URL 下载及文件保存需另行调用相应能力。
媒体沿用固定 host 的规则；经过原生保留与格式化之后，适配层的文本预算不再增加另一套音频或图片过滤。
